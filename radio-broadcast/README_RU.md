# RUN-156 — VELAR RADIO: настоящее интернет-вещание

## Архитектура
VELAR RADIO должен быть единым непрерывным серверным потоком, а не синхронным набором YouTube iframe. Администратор нажимает «Начать трансляцию» в Studio → защищённая Firebase Callable Function проверяет вход Google + vmm_admins/{uid}.enabled → даёт команду AzuraCast → Liquidsoap AutoDJ формирует общую очередь из разрешённых MP3/FLAC → Icecast раздаёт поток всем слушателям. Закрытие Studio не влияет на эфир.

Слушатель на сайте или отдельной странице получает **один HTTPS MP3/AAC поток**, нажимает «Слушать» (требование мобильных браузеров), после чего мини-плеер продолжает звучать в том числе при визуальном сворачивании. Воспроизведение под блокировкой iPhone зависит от поддержки Safari/PWA и подтверждается только на устройстве.

## Подключение
1. Выбрать постоянно работающий AzuraCast-хостинг или свой VPS с TLS и резервированием.
2. Загрузить мастер-фонограммы **с разрешением на интернет-вещание** и создать playlist AutoDJ с shuffle, метаданными, jingles по желанию. Нельзя брать аудио напрямую из YouTube/Spotify/Apple Music: ссылки не являются лицензией на отдельную ретрансляцию.
3. Настроить HTTPS URL прямого потока Icecast (позднее публичное поле streamUrl в Studio). Проверить, что он играет в HTML5 audio в Safari.
4. На **существующем** Firebase-проекте разместить radio-broadcast/functions/index.js как Callable Function velarRadioControl. На сервере настроить AZURACAST_URL (https origin), AZURACAST_STATION_ID (число) и Secret Manager AZURACAST_API_KEY. Не передавать ключ браузеру, GitHub, Firestore или публичному JS.
5. API команды: status, start, stop. Сервер проверяет Firebase auth + существующего одобренного администратора. Фронтенд не должен считать accepted:true доказательством, что звук уже идёт: необходим статус AutoDJ/активного потока.
6. После подключения сервиса включить режим сервера в Studio, интегрировать публичный HTML5 плеер и кнопки админа; не отключать существующие способы YouTube/Spotify/Apple Music, пока сервер не введён в эксплуатацию.

## Приёмочные проверки
- Старт однократно из Studio, AutoDJ продолжает работу при закрытии браузера администратора.
- Вторая вкладка, другой iPhone и компьютер слышат **один момент общего потока**.
- У посетителя нет доступа к API start/stop; администратор без Google/email_verified/rights отклонён.
- Плеер стартует компактно, раскрытие/сворачивание не удаляет audio и не сбрасывает позицию.
- Пауза слушателя не влияет на общую трансляцию.
- iPhone блокировка/разблокировка, переключение вкладки, следующая песня, отсутствие сети.
- Сервер недоступен → честный статус, без ложного «В эфире», автоматическое восстановление ограничено браузером.
