# VELARDREAM — журнал работ и решений

**Дата актуализации:** 2026-11-11. **Источник истины:** GitHub-репозиторий `velardream-ctrl/velar-music-manager`, ветка `main` плюс открытые PR. Этот журнал — навигация по реальным изменениям, **а не замена Git/CI**.

## Правила ведения
- Каждая значимая работа получает идентификатор `RUN-NNN`, цель и ветку/PR.
- Сразу вносить запись `НАЧАЛ`: проблема, воспроизведение, затронутые файлы, план, риски.
- После изменений вносить `ПРОВЕРКА`: команды и фактический результат CI, ручные проверки, неудачи.
- Запись `ЗАВЕРШИЛ` допустима **только после** слияния PR и проверки основных условий. Если ручная проверка на iPhone ещё нужна, указать это отдельно.
- Любую неудачу, выявленную на реальном устройстве, описывать с симптомом и способом воспроизведения, без личных текстов и токенов.
- Запрещено «исправлять» журнал задним числом с удалением неудач: добавлять новую запись с объяснением.
- Перед новым RUN прочитать [протокол передачи](PROJECT_HANDOFF_RU.md), последние строки этого журнала, PR и результаты CI.

## Как определить реальное состояние
1. Сравнить `main`, открытые PR и GitHub Actions; документы 9 ноября могут быть устаревшими.
2. До каждой публикации запускать `npm test` (Node.js >=18) и смотреть вывод всех тестов. Зелёный CI **не означает** проверенного iPhone/Google OAuth.
3. Смотреть последние наблюдения владельца в этом чате: воспроизведение FLAC для «Дикая вишня» 35,3 МБ на iPhone подтверждено скриншотом; галочка «Офлайн» отображалась, но запуск без интернета ещё не проверен.
4. При ошибке составить последовательность: точный экран → действие → сообщение → версия/PR → сетевые зависимости → последний успешный шаг.
5. Не удалять и не переписывать исходные файлы Google Drive, записи каталога, тексты, историю изменений и резервную копию без явно согласованной миграции.


### 2026-11-11 — RUN-053 — НАЧАЛ / ПРОВЕРКА: карандаш управления записью
- **Запрос владельца:** при обычном прослушивании фонограммы не показывать опасные элементы удаления и удаления офлайн-копии; открыть их только по значку редактирования в панели «Прослушивание». Исключить случайные дубли при загрузке одного и того же варианта.
- **Наблюдение на iPhone:** файл \`dikaya_vishnya__minusovka.flac\` (35,3 МБ) воспроизводится, офлайн-подборка содержит 2 записи (в сумме около 59 МБ); кнопка «В корзину» и галочка «Офлайн» были доступны прямо в обычной строке, что неудобно при выступлении.
- **Ветка:** \`fix/run053-player-edit-guard\`; PR будет связан после создания.
- **Изменения:** \`studio/recordings.js\` — карандаш около «Прослушивание», закрытая по умолчанию панель управления **текущим выбранным аудиофайлом**; кнопка «Сохранить офлайн»/«Убрать из офлайна», а также «В корзину Google Drive» доступны только после раскрытия карандаша. Звук, название песни и текст не меняются. При выборе другой композиции, выходе из раздела или сбросе сессии меню автоматически закрывается.

Удаление офлайн-копии требует подтверждения, корзина Google Drive сохраняет существующую проверку имени, папки, прав и отдельный вопрос подтверждения. Повторная загрузка уже имеющегося варианта «Минусовка» требует явного согласия до начала передачи.
- **Статические активы:** \`studio/recordings.css\`, \`studio/index.html\` и \`sw.js\` получают согласованные версии без очистки личного IndexedDB или удаления оригиналов из Google Drive.
- **Регрессионные тесты:** \`tests/test-player-edit-guard.mjs\` плюс все существующие тесты; итог CI/PR записать после проверки.
- **Ручная проверка остаётся:** открыть на iPhone фонограмму «Дикая вишня», начать воспроизведение, раскрыть карандаш; проверить скрытые действия и подтверждения; сменить песню, возвратиться и убедиться, что редактирование закрылось. Проверить отсутствие дублей при повторной загрузке одинакового варианта.
