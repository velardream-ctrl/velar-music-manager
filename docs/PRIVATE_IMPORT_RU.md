# VELARDREAM Studio — безопасный импорт данных прежнего VMM

Статус: инструмент переноса подготовлен. Личные записи в GitHub **НЕ загружаются**. Прошедшая GitHub CI проверка кода сама по себе **не означает**, что данные уже находятся в Firestore.

## Как загрузить личный файл

1. Скачать **личный** `VELARDREAM_PRIVATE_IMPORT_2026-11-09.json` из сообщения ChatGPT и сохранить в приложение «Файлы» на iPhone. **Не публиковать** файл, не прикладывать к issue и не загружать в GitHub.
2. Открыть https://velardream.com/studio/ и войти в Google-аккаунт владельца с разрешением `vmm_admins/{uid}.enabled=true`. До входа кнопка импорта недоступна.
3. Раскрыть раздел «Импорт данных из старого VMM · приватно», выбрать JSON из «Файлы», нажать **Проверить файл**. Должно появиться 1108 записей: 21 текст, 278 записей каталога, 266 предложений ссылок, 543 события журнала.
4. Отметить галочку согласия и нажать **Импортировать новые записи**. Требуется интернет. После предварительной проверки база покажет, сколько документов уже есть; они **будут пропущены**, а не заменены.
5. Подтвердить системный диалог и дождаться выполнения. Импорт идёт партиями по 175 записей. При сетевой ошибке не удалять исходный файл: последующий запуск пропустит ранее созданные документы.
6. Нажать «Обновить кабинет». Тексты появятся во вкладке «Тексты песен»; каталог — в «Каталог релизов», предложения ссылок — в «Площадки и ссылки», журнал — в «Журнал».

## Источники и безопасность

Экспорт сделан из **приватной резервной копии** `VELAR_VMM_SOURCE_BACKUP_2026-11-09_READ_ONLY_COPY`, а не из старой пустой вкладки `VMM · Тексты`. Оригинал Google Sheets не менялся. В резервной копии разделы «Контакты», «Рассылки», «VMM · Фонограммы» и «VMM · Площадки» не содержали записей. Инструмент переносит только четыре заполненные активные вкладки VMM. Другие вспомогательные таблицы YouTube, FreshTunes, истории ссылок и архива требуют отдельной проверки и не импортируются автоматически.

Содержимое JSON не встроено ни в HTML, ни в JavaScript публичного GitHub Pages. Выбор файла происходит локально в браузере, загрузка идёт через Firebase SDK непосредственно в Firestore после серверной проверки `vmm_admins/{uid}`. В режиме офлайн **первичный импорт невозможен**. Firestore IndexedDB может хранить просмотренные приватные записи на данном устройстве; не выполнять вход на чужом телефоне без отдельной защиты и очистки кэша.

## Повторные запуски

Для каждой строки используется стабильный ID: собственный UUID для текста/ссылки, `catalog-rNNNN` для каталога, `legacy-log-rNNNN` для журнала. Перед переносом Studio проверяет серверные документы и пропускает совпадения. Поэтому повторный запуск возможен после сетевой ошибки. Документы, которые были позже отредактированы в Studio, автоматически не перезаписываются экспортом.

**Контроль:** после загрузки сверить четыре количества в защищённой Firestore и вручную проверить минимум три текста, в том числе многострочные записи, несколько UPC/ISRC и один журнал. Отрицательный тест чужого Google-аккаунта нужен до открытия любых личных страниц другим пользователям.
