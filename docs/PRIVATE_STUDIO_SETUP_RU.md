# VELARDREAM / закрытая музыкальная мастерская — этап 1

## Что подготовлено
Адрес: `https://velardream.com/studio/` — отдельная страница **без ссылок с публичного сайта**. Она технически общедоступна, как и весь GitHub Pages, но **не содержит личных данных**. После подключения Firebase войти в рабочую область можно только через Google и проверку права владельца на Firestore. Публичная конфигурация Firebase Web App подключена в коде. Включён провайдер Google (подтверждено владельцем на скриншоте). При этом **Cloud Firestore ещё не подтверждён как созданный, правила доступа не опубликованы, и UID администратора ещё не зарегистрирован**. Вход и чтение личных материалов нельзя считать работающими до проверки всех этих этапов.

Интерфейс: тексты песен (редактор, базовая печать A4/PDF), заготовки каталога, фонограмм, площадок и ссылок, контактов, рассылок, журнала. **Не утверждать**, что все функции старого Apps Script уже перенесены: актуальная версия исходников VMM v1.3 ещё не считана, а Firestore не настроен.

## Почему нужен отдельный Firebase
Сайт GitHub Pages полностью публичен: `noindex`, скрытое меню, слово `admin` в URL и вход в Google НЕ защищают контент. Хранить здесь стихи, контакты, переписку, электронные адреса нельзя. Права доступа должны проверяться Firestore Security Rules на сервере. Firebase-проект Sanastoyhteisö не использовать.

## Для владельца: будущая минимальная настройка (после публикации основы)
1. В https://console.firebase.google.com создать **отдельный** Firebase проект, например `velardream-records-studio`. Оставить бесплатный тариф Spark; ничего не менять в Sanastoyhteisö.
2. Authentication → Sign-in method → включить Google. Authentication → Settings → Authorized domains → добавить `velardream.com` (при необходимости `www.velardream.com`).
3. Создать Cloud Firestore с закрытыми правилами; до применения финального правила оставить deny-all.
4. В настройках проекта создать Web App и скопировать **публичный** объект Firebase Web Config (`apiKey`, `authDomain`, `projectId`, `appId`); этот объект не является сервисным ключом. **НИКОГДА** не копировать сюда `serviceAccount`, private key, OAuth client secret, токены доступа.
5. **Выполнено 09.11.2026:** в `studio/firebase-config.js` уже записан публичный конфигурационный объект именно отдельного проекта `velardream-records-studio`. Повторно его не заменять. Используется Google popup с выбором аккаунта. Теперь необходимо проверить Authorized domains и доступность входа на сайте.
6. После входа взять Firebase Auth UID аккаунта владельца из раздела Authentication → Users. В Firestore Console **вручную** создать документ `vmm_admins/{UID}` с полем `enabled: true` типа Boolean. Не создавать эту запись из публичного сайта. Убедиться, что UID скопирован верно и указан исключительно в **новом** Firebase-проекте.
7. Применить проверенные правила `firestore.rules` в этом новом проекте, проверить отрицательный сценарий чужого Google-аккаунта и положительный для владельца. Пользователь без `vmm_admins/{uid}` не может читать песни.
8. Только после этого импортировать данные из **отдельной приватной резервной копии Google Sheets** в коллекции Firestore, проверив соответствие записей, отсутствие дублей, сохранение языка, версии, UPC и каталожной строки. Таблицу-источник не удалять.

## Безопасность и офлайн
Воспроизводить данные приватно **только после аутентификации**. `firestore.rules` пока **не развёрнуты**. Режим Firestore IndexedDB persistence подготовлен для работы после первого входа в сеть, но корректную офлайн-очередь, конфликты редактирования, выход из аккаунта и удаление локальных копий необходимо проверить отдельно, прежде чем называть офлайн-редактор готовым. Service Worker публичного сайта не должен кэшировать приватную базу.

## Текущие ограничения
- Google-провайдер включён, публичный Web App config записан в коде. Работоспособность Google-входа на домене **ещё не подтверждена**; авторизованные домены и разрешения Firestore требуют проверки.
- Тексты песен **ещё не импортированы** в Firestore.
- Разделы кроме текстов — пока запланированы, не полная копия функциональности старого VMM.
- Авторизация по Google без проверки документа `vmm_admins/{uid}` не открывает кабинет.
- Печатная форма A4/PDF — базовая, не точная копия Lyrics Studio v1.3; окончательная верстка после получения текущего Apps Script.
