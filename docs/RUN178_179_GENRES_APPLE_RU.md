# RUN-178 / RUN-179 — жанры по галочкам и Apple Music в подборках

Дата: 17 ноября 2026 года. Репозиторий: velardream-ctrl/velar-music-manager.
Ветка: `feat/run178-genre-song-assignments-20261117`.
Исходная точка: `b8c9db3f9ac4f2d6ef7fe0e4524c091a561b0d58`.

## Требование владельца
В разделе Studio → Главная страница → Жанры назначение максимально простое:
выбрать жанр, поставить **одну галочку** рядом с нужной песней. Не показывать
отдельных галочек Spotify/YouTube/Apple Music. Песня уже принадлежит единому
каталогу; её официальные ссылки должны подхватываться **автоматически**.
Один трек можно назначить в несколько жанров, но нельзя продублировать
в пределах одного жанра. Жанры можно создавать, переименовывать, менять
порядок, скрывать и удалять. Пример: «Опера» → «Новая опера».

Отдельное требование RUN-179: в «Темах песен» на старом iPad при выборе песни
ранее были только Spotify/YouTube. Добавить Apple Music в существующий общий
редактор тем/языков/альбомов с 1–3 независимыми источниками **без
дублирования композиции**, не изменяя авторские песни и Firebase Rules.

## Реализация
- `genres.tags` прежних опубликованных страниц мигрируют при чтении в
  `genres.entries` с устойчивыми `id`, `visible`, пустыми `songIds` и
  `tracks`; старые названия не теряются и песня автоматически не угадывается.
- Studio жанров использует только `songIds` из приватного каталога
  `vmm_catalog`. Одна галочка / одна запись каталога; поиск и разбивка по
  40 строк на страницу позволяют работать с сотнями песен на старом iPad.
- Никаких отдельный выборов провайдера в жанрах. При ручной публикации
  серверно проверенный (по правилам Firebase) приватный каталог читается
  авторизованным редактором: публичные `tracks` пересобираются из
  имеющихся `song.links.spotify/youtube/appleMusic` по белому списку URL.
  Отсутствие всех ссылок не удаляет `songIds`: песня остаётся назначенной
  и появится после добавления подтверждённой ссылки и следующей публикации.
  Если назначенного ID нет в каталоге — публикация останавливается.
- Одна композиция может быть назначена нескольким жанрам, ссылки не вводятся
  повторно. Смена названия жанра не меняет его устойчивый код и связи.
- Новый `genres-public.js` показывает на сайте кликабельные жанры и песни
  с уже подключёнными платформами, используя общий `public-song-ui.js`.
  Без автономного считывания приватного каталога и без автозапуска музыки.
- Общий `languageTrack` теперь принимает три официальные ссылки,
  сохраняет старые записи с одним/двумя источниками и запрещает
  произвольные URL, дубли площадок и повторы ссылок.
- `studio/landing-editor.js` в темах, языках и альбомах показывает
  Spotify, YouTube **и Apple Music** как независимые опции. В жанрах —
  только галочка композиции, без этих опций.
- Версии публичных и Studio-скриптов в HTML/Service Worker обновлены
  для корректного кэширования Safari. Вёрстку кристалла, радио,
  панель входа, Firestore Rules, DNS и рабочие данные не меняли.

## Безопасность и совместимость
- Работа с жанрами и источниками происходит через редактор черновика;
  посетитель видит изменения только после явного «Опубликовать».
- Не сохраняем приватные записи каталога, тексты, MP3, токены, Drive URL
  или пароли в публичной странице. Источники строго валидируются.
- ES5-код рассчитан на старый Safari 12. Новые жанровые функции
  не используют CSS/JS для поворота iPad или системной клавиатуры.
- Жанровый публичный документ и черновик продолжают использовать
  исходные коллекции `vmm_public_pages/landing` и
  `vmm_public_drafts/landing`, `schemaVersion: 1`.
- Сохранить предыдущую успешную версию GitHub для rollback.
- Проверка ручной загрузки на старом iPad владельца остаётся отдельной:
  CI не воспроизводит аппаратный Safari.
