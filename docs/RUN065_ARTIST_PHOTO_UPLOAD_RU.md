# RUN-065 — Фотография артиста с кадрированием

Дата: 2026-11-11. Статус: КОД В ОТДЕЛЬНОЙ ВЕТКЕ, FIREBASE STORAGE НЕ НАСТРОЕН.

## Задача
Добавить во вкладку «Главная страница → Артисты» выбор фотографии с телефона или компьютера. На изображении можно перемещать кадр пальцем или мышью, менять масштаб, затем выбрать квадратный или круглый способ показа. Сохраняется один квадратный оптимизированный файл, круг — только CSS-маска на странице.

## Как работает
- Новая страница для файлов не создаётся: фото подготавливает браузер, а передаёт напрямую в Firebase Storage через проверенную Google-авторизацию администратора.
- Источник до 20 МБ; WebP, либо JPEG при отсутствии поддержки; квадрат до 720×720 пикселей, размер до 320 КБ.
- В Firestore остаётся только HTTPS-адрес готовой фотографии и настройка оформления. Никаких двоичных фотографий или base64 в Firestore. Никаких фотографий в GitHub.
- После кнопки загрузки пользователь отдельно нажимает «Сохранить черновик», затем «Опубликовать». Никакие частные песни, тексты, фонограммы или исходный каталог не становятся публичными.
- Схема разрешает URL строго указанной публичной папки нашего Firebase Storage; Google Drive и приватные URL запрещены.
- Правила Firestore, данные Google Sheets и оригинальные записи не меняются.

## Требуемое ручное подключение
Cloud Storage for Firebase в 2026 году требует тариф Blaze, даже если фактические расходы остаются в бесплатной квоте. На Spark сервис не работает (HTTP 402/403). **Не включать биллинг без решения владельца.**
Перед активацией: сохранить действующие правила Storage, включить Storage для проекта velardream-records-studio, вручную просмотреть storage.rules и применить только совместимые изменения. Правила с firestore.get могут запросить межсервисное разрешение. До этого кнопка сможет подготовить фото, но реальная отправка завершится сообщением об ошибке.

## Ручные проверки после настройки
1. Вход подтверждённого администратора, создание карточки DJ Velar, вертикальный и горизонтальный исходник.
2. Перетаскивание пальцем на старом iPad/iPhone Safari, масштаб, WebP/JPEG, размер не более 320 КБ.
3. Загрузка не меняет публичный сайт; только явная публикация показывает выбранный квадрат или круг.
4. Посторонний аккаунт не загружает и не удаляет фото, анонимные пользователи не перечисляют файлы.
5. Проверка расходов, обновлений PWA, ошибок HEIC и отсутствие регрессий музыкальной библиотеки.

Вся работа ведётся через docs/WORK_ACTIVITY_LOG_RU.md в формате НАЧАЛ → ПРОВЕРКА → ЗАВЕРШИЛ. Реальные проверки и развёртывание Storage пока открыты.
