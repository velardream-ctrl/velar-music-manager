# RUN-193 — Первый запрос DJ Velar AI прерывается на iPhone
Дата: 17.11.2026.

## Наблюдение
Пользователь подключил Cloudflare Worker, AI binding и секрет. Диагностика GET /health вернула ready:true, модель @cf/meta/llama-3.1-8b-instruct-fp8, publicEnabled:false. В Studio → Главная страница → Помощник VELAR → Лаборатория тестовый запрос завершился «Fetch is aborted».
Причина, найденная в исходном коде Studio: старый `studio/ai-lab.js` прерывал всякий запрос через 12 000 мс (`AbortController.abort()`). Это не подтверждает ни неисправность модели, ни превышение квоты. `/health` не вызывает нейросеть и не измеряет фактическую генерацию.

## Исправлено
Ожидание первого ответа увеличено до 60 с; в интерфейсе отображается прошедшее время (3-секундный интервал). Ошибки тайм-аута, сетевого подключения и ответа API диагностируются раздельно. После завершения/ошибки таймеры убираются, кнопка вновь активна. Обновлён URL ai-lab.js до v=2, версия PWA-кэша Studio до RUN-193 для обхода сохранённой на iPhone копии.
Не изменены Worker, токен, AI binding, публичный DJ Velar, Firestore Rules, радио и кристалл. Публичный ИИ остаётся отключённым.

## Проверить вручную
1. Открыть обновлённую Studio обычной вкладкой Safari, не очищая локальные черновики.
2. Главная страница → Помощник VELAR → Лаборатория. Снова вставить адрес Worker и сохранённый секрет (не присылать его и не сохранять в GitHub).
3. Задать короткий вопрос: «Привет! Кто ты?» Нажать «Проверить ответ модели». До 60 с может отображаться ожидание.
4. Если ответ есть — проверить ещё русский, финский и английский. Если снова превышено 60 секунд, открыть Cloudflare Dashboard → Workers → dj-velar-private-lab → Observability → Logs и найти POST /v1/owner-test, ошибки или AI-quota, без раскрытия секретов.
5. Считать рабочим только после реального ответа модели; ready:true не достаточен.

## Дополнительно
Если сервер вернул 503 с `ai_unavailable_or_quota_exhausted`, исследовать доступность модели и тарифную квоту в Cloudflare, а не многократно перезапускать без диагностики.
