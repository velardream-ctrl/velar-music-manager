# Velar Dream — решение о постоянном тестовом сайте (20.11.2026)

**Статус:** решение владельца принято; инфраструктура ещё не создана и не опубликована.

## Решение
- Создать отдельный GitHub-репозиторий `velardream-ctrl/velardream-preview` и независимую публикацию GitHub Pages, ориентировочный адрес `https://velardream-ctrl.github.io/velardream-preview/` (не считать действующим до проверки).
- Использовать этот сайт как постоянный staging для всех будущих функций и исправлений Velar Dream.
- Production `https://velardream.com/` сейчас публикуется через GitHub Pages из `velar-music-manager`, ветка `main`, каталог `/(root)`. Не менять настройки Pages production, не отключать публикацию, не менять CNAME/DNS.
- Сначала тестировать на staging (включая iPhone Safari и старый iPad), затем по явному одобрению владельца и после проверок переносить изменения через PR в production.
- Не подключать тестовую среду с правами записи к рабочей Firebase; отдельные конфигурация/данные либо строго read-only публичные данные. Никаких production-секретов в тестовом репозитории.
- Вести отдельный журнал staging: что проверено, SHA/PR, тесты, обнаруженные ошибки, решение о выпуске, инструкция отката. После каждого существенного изменения обновлять журнал и инструкции восстановления.
- Не требовать платного Work; использовать доступные GitHub-инструменты и ручную настройку только когда необходимо.
