# RUN-061 — подключение CMS публичной главной страницы

## Что создано

В защищённой студии появилась вкладка **Главная страница**: первый экран, артисты, релизы, жанры, о проекте и публикация. Разделы не читают приватные тексты и фонограммы. Карточки артистов и релизов вводятся вручную и попадают на публичный сайт **только после явной публикации**.

| Firestore | Доступ |
|---|---|
| \`vmm_public_drafts/landing\` | Читать и редактировать только проверенному администратору \`vmm_admins/{uid}.enabled=true\` |
| \`vmm_public_pages/landing\` | Анонимно читать **только этот документ**, если \`status=published\`; писать только администратору |
| \`vmm_catalog\`, \`vmm_lyrics\`, \`vmm_recordings\` | Как и прежде, **не публичные** |

## Критически важный ручной этап

**Внимание:** файл \`firestore.rules\` в репозитории помечен **STAGED — NOT DEPLOYED**. Это НЕ гарантирует совпадения с реально действующими правилами Firebase. **Нельзя просто заменить текущие правила целым файлом из GitHub**: можно случайно закрыть старые работающие коллекции либо изменить их защиту.

1. В Firebase Console выбери проект **velardream-records-studio**, затем Firestore Database → Rules.
2. Сохрани точную резервную копию *действующих* правил в приватном месте.
3. Сравни их с текущим \`firestore.rules\` в GitHub. Добавь **только** два новых правила для \`vmm_public_drafts\` и \`vmm_public_pages\` и вспомогательную \`validLandingWrite\` из RUN-061. Оставь существующие разрешения частных коллекций без изменений.
4. В тестовом симуляторе/эмуляторе проверь: посторонний не читает черновики и приватные коллекции; анонимный пользователь может получить только \`vmm_public_pages/landing\` после публикации; листинг запрещён; администратор с подтверждённым Google-аккаунтом и \`vmm_admins/{uid}.enabled=true\` может записывать оба документа.
5. Нажми **Publish** для правил только после проверки.
6. Открой \`https://velardream.com/studio/#vmm-landing\`, авторизуйся, внеси небольшой безопасный текст, нажми **Сохранить черновик**. Главная в этот момент не должна измениться.
7. Нажми **Опубликовать**, затем открой \`https://velardream.com/\` в отдельном окне, проверь появление текста. Для второй проверки временно отключи интернет: существующий статический макет должен остаться доступен.

Если правил нет, редактор покажет отказ доступа. Публикация в коде не означает, что Firestore уже развернут.

## Контроль безопасности и восстановление

- Не добавляй сюда частные адреса, тексты песен, непубличные ссылки Drive и записи студии. Разрешены только осознанно опубликованные данные и HTTPS-ссылки.
- Сохранение черновика не публикует данные; публикация атомарно заменяет **только** документ \`vmm_public_pages/landing\`.
- Версии черновика и публикации проверяются транзакциями. Изменение с другого устройства вызывает конфликт вместо молчаливой перезаписи.
- Кнопка **Вернуть опубликованную версию** восстанавливает её *в редакторе*, но не публикует автоматически. Для полноценной истории версий нужен отдельный архив публикаций — в RUN-061 он не включён.
- При ошибке чтения публичного документа сайт сохраняет нынешнюю статическую страницу («Скоро»), а не показывает приватную базу.
- Основной репозиторий: \`velardream-ctrl/velar-music-manager\`; журнал действий: \`docs/WORK_ACTIVITY_LOG_RU.md\`.
