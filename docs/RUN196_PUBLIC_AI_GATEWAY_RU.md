# RUN-196 — DJ Velar: публичный AI и локальный резерв

Дата: 17.11.2026. Статус: **код подготовлен в отдельной ветке, Cloudflare-публикация не выполнена**.

## Что сделано
- В Cloudflare Worker добавлен `POST /v1/public-chat` отдельно от закрытого `/v1/owner-test`, без секретного токена в браузере.
- Публичный endpoint **выключен по умолчанию** и возвращает 503, пока секретный флаг Cloudflare `PUBLIC_AI_ENABLED` не равен строке `true`.
- Отсутствие серверного Cloudflare Rate Limiting binding `PUBLIC_RATE_LIMITER` или IP приводит к 503 без обращения к модели; превышение лимита — 429. Для идентификации используется заголовок `CF-Connecting-IP`, который должен выставляться Cloudflare, а не клиентом.
- Локальные команды радио, песни, опубликованные ссылки и ответы владельца имеют приоритет. Только незнакомые вопросы направляются к AI. При отключении AI, тайм-ауте, ошибке или исчерпании квоты включается старый локальный ответ. Локальные правила, существующие записи и PWA остаются на месте.
- Источник ответа сохраняется только в DOM текущей вкладки (`data-response-source`), не в Firestore.
- Посетителю сообщается, что неизвестные вопросы могут направляться Cloudflare AI. Не сохранять личные диалоги и секреты в логах.
- Новый тест `tests/test-public-ai-gateway.mjs`, включён в `npm test`.

## Необходимые действия в Cloudflare (ещё не выполнены)
1. Сохранить резервную копию текущего Worker `dj-velar-private-lab` и его настроек.
2. Загрузить актуальный код `cloudflare/dj-velar-owner-lab.js` и удостовериться, что `/v1/owner-test` по-прежнему требует секрет владельца.
3. Привязать к Worker существующий Workers AI binding с именем `AI`.
4. Создать Cloudflare Rate Limiting binding `PUBLIC_RATE_LIMITER`, задать строгий лимит, например 5 запросов в минуту на IP с учётом бесплатного тарифа; проверить фактический тариф и поддерживаемые настройки в Dashboard. Если тариф не поддерживает привязку, **не включать публичный AI**.
5. Назначить отдельный hostname `ai.velardream.com` Worker через Cloudflare route/custom domain, проверить TLS и CORS. До этого браузерные запросы будут попадать в локальный fallback.
6. Установить `PUBLIC_AI_ENABLED=true` **только после** проверки нагрузочных лимитов и отсутствия открытого неограниченного маршрута. Никогда не публиковать `VELAR_OWNER_TEST_TOKEN`.
7. Проверить запрос «Что ты умеешь?» на опубликованном сайте, пустую квоту, временную потерю интернета, искусственный 429, медленный ответ, старый iPad Safari и радио. Проверить `/health`: его `publicEnabled:false` пока отражает статус закрытой лаборатории и не доказывает включённый публичный маршрут.

## Известные границы
- Код в GitHub **не разворачивает** сам Cloudflare Worker и DNS автоматически.
- Публичное AI-обслуживание будет работать только после защищённого Cloudflare-развёртывания.
- Обратный путь без вмешательства в сайт: вернуть `PUBLIC_AI_ENABLED=false`; посетители продолжат получать ответы от локального DJ Velar.
- JS содержит фиксированный публичный адрес `https://ai.velardream.com/v1/public-chat`; не заменять его на секретный `/v1/owner-test`.

## Дополнение: второй предохранитель перед активацией
- На стороне браузера `window.VELAR_PUBLIC_AI_ENABLED` по умолчанию отсутствует/false, поэтому публичный DJ Velar **не отправляет** вопросов в AI даже при наличии нового JS. Он мгновенно отвечает по старым локальным правилам.
- После полностью настроенного Worker + ограничений + TLS нужно отдельно разрешить запуск в клиентском коде и опубликовать согласованную новую версию; при отключённом серверном флаге и rate-limiter модель всё равно не вызывается.
- Не считать слияние PR включением AI для посетителей. Нельзя менять этот флаг без предварительной проверки Cloudflare и обновления журналов.

## RUN-198 — уточнение лимитов и подготовка к Cloudflare (17.11.2026)
- После RUN-197 уточнено: **нет подключённого инструмента Cloudflare**, поэтому конфигурация и Worker остаются проектными файлами GitHub, а не работающей публичной интеграцией. Проверка через браузер не подтвердила доступность `https://ai.velardream.com/v1/public-chat`; это не доказательство отсутствия DNS, но реальный endpoint не проверен.
- Публичный Worker теперь требует **два** bindings: `PUBLIC_RATE_LIMITER` (на посетителя/IP) и `PUBLIC_GLOBAL_RATE_LIMITER` (один общий ключ для ограничений совокупного потока по каждой точке Cloudflare). Без любого из bindings запрос завершится 503 до обращения к модели. При отказе любого — 429 до обращения к модели.
- Пример конфигурации без токенов: `cloudflare/wrangler.example.toml`. Он **не должен развёртываться без проверки**: namespace IDs примерные, имя существующего Worker необходимо сверить, назначение Custom Domain намеренно закомментировано, `PUBLIC_AI_ENABLED=false`.
- **Важно:** Cloudflare Rate Limiting приблизителен и привязан к location. Даже дополнительный общий ограничитель не создаёт строгого единого мирового суточного лимита и не гарантирует нулевых расходов. Для строгого бюджета использовать Durable Objects с атомарным счётчиком и проверять фактическую тарификацию Workers AI. Источник: https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/.
- Перед включением требуется сверить в Cloudflare действующую приватную лабораторию, создать bindings, подтвердить DNS/TLS, протестировать OPTIONS/CORS/403/429/503/200 и нагрузку в пределах разрешённых правил; дополнить ненавязчивую политику конфиденциальности до передачи вопросов AI. Только затем разрешать публичный флаг на сервере и отдельно в клиенте. Никаких реальных клиентских запросов в Cloudflare на этом этапе нет.

## RUN-198 — СЧЁТЧИК В НАСТРОЙКАХ ПОМОЩНИКА
- В Studio откройте «Главная страница → Помощник VELAR → Лаборатория DJ Velar AI». Введите собственный адрес Worker с окончанием `/v1/owner-test` и временно — секрет владельца (не сохраняется). Нажмите **«Обновить счётчик AI»**. Панель запрашивает только `GET /v1/owner-stats` с токеном и показывает день UTC, `used`, `succeeded`, `failed`, заданный серверный `limit` и `remaining`.
- **Пока Worker из GitHub не развёрнут**, счётчик пишет о недоступности. Не выводить фиктивные 0/100 как реальные остатки. Число `used` — резервированные попытки вызова AI в публичном маршруте; ошибки модели тоже расходуют попытки. Лабораторные `/v1/owner-test` запросы **в этот счётчик не входят**. Это не число токенов и не счёт Cloudflare.
- В `cloudflare/ai-budget.js` один Durable Object `VelarAiBudget` сохраняет общее дневное число (UTC), успехи и ошибки. Binding `PUBLIC_AI_BUDGET` обязателен. Отсутствие объекта, неправильный лимит `PUBLIC_AI_DAILY_LIMIT` (1–1000) или ошибка резервирования блокируют публичный AI до вызова модели. Отдельные приблизительные Cloudflare Rate Limiting bindings остаются обязательными.
- Пример развёртывания `cloudflare/wrangler.example.toml` содержит миграцию `new_sqlite_classes` и отключённый публичный флаг. Секрет владельца никогда не включать в git. Перед развёртыванием проверить фактический Worker, namespace IDs и поддержку SQLite Durable Objects на плане. После развёртывания и проверок проверить `owner-stats` 401 без токена / 200 с токеном, предел 429, аварийный 503 и живой AI 200. Убедиться, что старый локальный DJ Velar работает при каждом отказе.
- Информирование о возможной передаче вопроса стороннему обработчику оформить ненавязчиво в политике конфиденциальности перед публичным включением (по просьбе владельца не добавлять рекламирующую AI подсказку обратно в чат).
- **Публикация GitHub сама по себе не включает Cloudflare**, не создаёт DNS/TLS и не гарантирует соответствия бесплатной квоте. Публичные переключатели пока OFF.
