# RUN-196 — DJ Velar: публичный AI и локальный резерв

Дата: 17.11.2026. Статус: **код подготовлен в отдельной ветке, Cloudflare-публикация не выполнена**.

## Что сделано
- В Cloudflare Worker добавлен `POST /v1/public-chat` отдельно от закрытого `/v1/owner-test`, без секретного токена в браузере.
- Публичный endpoint **выключен по умолчанию** и возвращает 503, пока секретный флаг Cloudflare `PUBLIC_AI_ENABLED` не равен строке `true`.
- Отсутствие серверного Cloudflare Rate Limiting binding `PUBLIC_RATE_LIMITER` или IP приводит к 503 без обращения к модели; превышение лимита — 429. Для идентификации используется заголовок `CF-Connecting-IP`, который должен выставляться Cloudflare, а не клиентом.
- Локальные команды радио, песни, опубликованные ссылки и ответы владельца имеют приоритет. Только незнакомые вопросы направляются к AI. При отключении AI, тайм-ауте, ошибке или исчерпании квоты включается старый локальный ответ. Локальные правила, существующие записи и PWA остаются на месте.
- Источник ответа сохраняется только в DOM текущей вкладки (`data-response-source`), не в Firestore.
- Посетителю сообщается, что неизвестные вопросы могут направляться Cloudflare AI. Не сохранять личные диалоги и секреты в логах.
- Новый тест `tests/test-public-ai-gateway.mjs`, включён в `npm test`.

## Необходимые действия в Cloudflare (ещё не выполнены)
1. Сохранить резервную копию текущего Worker `dj-velar-private-lab` и его настроек.
2. Загрузить актуальный код `cloudflare/dj-velar-owner-lab.js` и удостовериться, что `/v1/owner-test` по-прежнему требует секрет владельца.
3. Привязать к Worker существующий Workers AI binding с именем `AI`.
4. Создать Cloudflare Rate Limiting binding `PUBLIC_RATE_LIMITER`, задать строгий лимит, например 5 запросов в минуту на IP с учётом бесплатного тарифа; проверить фактический тариф и поддерживаемые настройки в Dashboard. Если тариф не поддерживает привязку, **не включать публичный AI**.
5. Назначить отдельный hostname `ai.velardream.com` Worker через Cloudflare route/custom domain, проверить TLS и CORS. До этого браузерные запросы будут попадать в локальный fallback.
6. Установить `PUBLIC_AI_ENABLED=true` **только после** проверки нагрузочных лимитов и отсутствия открытого неограниченного маршрута. Никогда не публиковать `VELAR_OWNER_TEST_TOKEN`.
7. Проверить запрос «Что ты умеешь?» на опубликованном сайте, пустую квоту, временную потерю интернета, искусственный 429, медленный ответ, старый iPad Safari и радио. Проверить `/health`: его `publicEnabled:false` пока отражает статус закрытой лаборатории и не доказывает включённый публичный маршрут.

## Известные границы
- Код в GitHub **не разворачивает** сам Cloudflare Worker и DNS автоматически.
- Публичное AI-обслуживание будет работать только после защищённого Cloudflare-развёртывания.
- Обратный путь без вмешательства в сайт: вернуть `PUBLIC_AI_ENABLED=false`; посетители продолжат получать ответы от локального DJ Velar.
- JS содержит фиксированный публичный адрес `https://ai.velardream.com/v1/public-chat`; не заменять его на секретный `/v1/owner-test`.

## Дополнение: второй предохранитель перед активацией
- На стороне браузера `window.VELAR_PUBLIC_AI_ENABLED` по умолчанию отсутствует/false, поэтому публичный DJ Velar **не отправляет** вопросов в AI даже при наличии нового JS. Он мгновенно отвечает по старым локальным правилам.
- После полностью настроенного Worker + ограничений + TLS нужно отдельно разрешить запуск в клиентском коде и опубликовать согласованную новую версию; при отключённом серверном флаге и rate-limiter модель всё равно не вызывается.
- Не считать слияние PR включением AI для посетителей. Нельзя менять этот флаг без предварительной проверки Cloudflare и обновления журналов.
