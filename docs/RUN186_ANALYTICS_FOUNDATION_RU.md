# RUN-186 — аналитика посещений и интереса к музыке
Дата: 17.11.2026.

## Запрос владельца
Админ-панель: посещения, посетители, открытия музыкальных плееров, рейтинг треков, источники (радио, артист, тема, язык, альбом). Отдельное включение публичного счётчика. Регистрации посетителей нет.

## Реализованный безопасный фундамент
В общую схему hero.analytics добавлены opt-in enabled/showPublic/showVisits/showActions/showTopTracks, редактируемый заголовок, срок хранения 30/90/180 дней. Настройки живут в существующем защищённом черновике Studio и публикуются отдельно.
В Studio → Главная страница → Статистика посещений появился редактор с честным статусом: сервер обработки событий ещё НЕ подключён, счётчики НЕ работают и не отображают фиктивные числа.
В analytics-public.js реализован fail-closed приём событий интерфейса: при отсутствии оператором заданного защищённого URL или явного согласия посетителя никакие запросы не отправляются. Согласие отдельно предлагается посетителю только после включения проверенного endpoint, отказ не препятствует использованию сайта.
Подключены события player_open в общей карточке песен для тем, языков, жанров, альбомов; в профиле артиста; на главной. radio_open и radio_next отмечают действия с радио. Это НАЖАТИЯ / открытия официального проигрывателя, не подтверждённые прослушивания. Выбор трека внутри внешнего Spotify/Apple iframe недоступен, а автоматическую смену YouTube-клипов нельзя достоверно считать этим счётчиком.
Контентные скрипты защищённого каталога, фонограммы, правила Firestore и приватные документы не менялись. Ни IP, ни cookies, ни location/фингерпринтинг скрипт не считывает.

## Что ещё НЕ реализовано / не включать как готовый счётчик
Нужен отдельный серверный приём событий с ограничением частоты, автоматическим отсечением ботов/накрутки, агрегатами по дням/треку/источнику и проверяемым доступом владельца. Отправка анонимных публичных записей прямо в Firestore запрещена существующими правилами и так должно оставаться.
Нужны загрузка реальных агрегатов в приватной админке, при необходимости публичный снимок только итогов, политика конфиденциальности, хранение/удаление данных и тесты на старых iPad.
Для уникальных посетителей необходим корректный метод оценки, а не простое число просмотров; для стран — лучше гео на сервере с немедленным отбрасыванием IP, если данные вообще нужны. Определить правовое основание и согласие посетителя согласно финским требованиям.
До завершения вышеуказанного аналитика остаётся отключённой. Владелец может проектировать параметры отображения, но не следует включать enabled в публичной версии до готовности защищённого сервиса.

## Правила будущего рейтинга
«Чаще открывают» = player_open по каноническому song ID; нельзя писать «прослушано», пока внешняя платформа не дала подтверждения начала воспроизведения. Для YouTube при доступности Player API можно отдельно вести подтверждённые события с версией и источником, но не считать их эквивалентом Spotify clicks.
Устойчивый идентификатор песни формируется по каталогу в защищённом backend; не вычислять идентичность только по названию (дубли, каверы и разные версии). Отдельно учитывать радио, темы, языки, карточки артиста.
