# RUN-182 — сверка уже существующих ссылок между каталогом и публикациями

Дата: 17 ноября 2026 года.
Репозиторий: `velardream-ctrl/velar-music-manager`
Ветка: `feat/run182-reconcile-existing-links-20261117`.

## Запрос владельца
До поиска новых песен в интернете необходимо найти и использовать **уже сохранённые**
Spotify/YouTube/Apple Music URL, особенно когда песня опубликована в теме,
языке, альбоме или подборке артиста только с одной площадкой.
Нельзя создавать дубликаты композиций и нельзя случайно приписать ссылку другой песне.

## Доступные источники и границы проверки
- Проверена схема текущего проекта: живой приватный `vmm_catalog`, отдельные
  документы `vmm_public_drafts/landing`, `vmm_public_pages/landing`,
  а также `vmm_links` для предложений и журналов.
- Прямого пользовательского доступа к Firebase через подключённые инструменты
  этого чата **нет**. Поэтому нельзя утверждать, что текущие 280 записей в базе
  уже проверены или изменены.
- В подключённом Google Drive обнаружен исторический read-only snapshot
  `VELAR_VMM_SOURCE_BACKUP_2026-11-09_READ_ONLY_COPY`. В листе «Каталог» 278
  заполненных строк, 260 Apple Music, 259 Spotify, 152 YouTube, и 150 записей
  с заполненными ссылками на все три площадки (состояние от 9 ноября; не live).
- Сопоставление этого snapshot со старой таблицей «VMM · Ссылки на проверку»
  указало на один возможный случай, требующий повторной проверки на текущих
  данных: «Bachata Rave», историческая подтверждённая ссылка YouTube
  в очереди отсутствует в соответствующей строке старого каталога.
  **ВНИМАНИЕ: основная строка каталога помечена «Требует проверки · ошибочная
  ссылка удалена 2026-10-20»**. Очередь сохранила старое «Подтверждено»,
  но оно не отменяет более позднюю отметку об ошибке. URL запрещено
  восстанавливать без новой ручной проверки владельцем.
  Автоматической записи в текущий Firebase по историческим данным НЕ делалось.
- Не выполнялся интернет-поиск недостающих ссылок; это отдельный будущий этап.

## Реализация в Studio
Раздел **Главная страница → Проверить и опубликовать**:
1. Нажать **«Проверить все прикреплённые песни»**. Авторизованный редактор
   читает свежий `vmm_catalog` только с сервера Firebase через действующий
   `authorized()` с Google verified и allowlist. Нет записей в Firebase.
2. Модуль `studio/existing-links-reconcile.js` проверяет источники уже
   назначенных `featuredTracks` артистов, языков, тем и альбомов.
   Жанры привязаны по `songIds`; их ссылки и прежде регенерируются при
   обычной публикации и не требуют отдельного копирования в черновик.
3. Сопоставление только по точным ID Spotify Track / YouTube Video /
   Apple Music Song (без fuzzy-сравнения названий). Один ID должен однозначно
   указывать на ровно одну запись каталога; столкновения/конфликты не меняются.
4. Старые ссылки остаются нетронутыми: только добавление отсутствующих
   подтверждённых ссылок других площадок; не более 3 на композицию.
   Ссылка из каталога проходит `API.songUrl` и публикационную валидацию.
5. Отчёт показывает число проверенных строк, найденных добавлений,
   неоднозначностей и пропусков, разбиение по разделам и до 20 примеров.
   Кнопка переноса требует дополнительного согласия владельца.
6. После переноса изменения находятся только **в локальном черновике**
   редактора. Сохранение в Firestore и публичная публикация — два отдельных
   действия со старой проверкой версий и конфликтов. Без нажатий владельца
   ни текущий каталог, ни опубликованные страницы не меняются.
7. При смене учётной записи, изменении черновика во время сканирования,
   офлайн-режиме и неполной загрузке каталога применение прекращается.

## Что пока не сделано
- Не сканировался текущий `vmm_links` и не переносились предлагаемые там
  ссылки в `vmm_catalog`. Возможные расхождения исторического Sheets
  и живого каталога требуют отдельной проверки по UPC, ISRC и ID с участием
  владельца. Старые снимки не считать актуальной правдой.
- Не добавлялись ссылки из интернета и не подтверждались внешние сервисы.
- Не изменялись Firebase Rules, права, DNS, радио, кристалл, загруженные
  песни, фонограммы и тексты.
- Аппаратный тест на старом iPad ещё не проведён.
