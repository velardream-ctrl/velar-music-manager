# RUN-183 — обложки и единые значки площадок в отдельных профилях артистов

Дата: 17 ноября 2026 года.
Репозиторий: `velardream-ctrl/velar-music-manager`.
Рабочая ветка: `fix/run183-artist-artwork-platform-controls-20261117`.

## Проблема от владельца

На `artist.html?id=...` раздел **«Лучшие песни»**:
- «Квадратные карточки» показывали большую ноту вместо реальных обложек.
- «Строки с обложками» показывали маленькую ноту вместо обложки.
- Переключатели Spotify, YouTube и Apple Music были старыми символами `♫/▶/♪`, визуально не совпадали с основными музыкальными разделами сайта.
- Компактный список без обложек уже был удобен и должен сохраниться.

## Причина
`artist-detail.js` создавал placeholder `♫` без попытки загрузить реальную обложку.
Отдельная `artist.html` не подключала `public-song-ui.js`, хотя общие разделы
используют его экспорт `VELAR_PUBLIC_SONGS.requestArtwork` с кэшем,
строгим Spotify oEmbed URL и fallback на ноту.

## Исправление
- `artist.html` теперь подключает **тот же** `public-song-ui.js?v=25`
  до `artist-detail.js?v=5`. Никакого дополнительного API или чтения
  приватных данных.
- Для опубликованных песен с обложками в режимах `tiles` / `covers`
  используется проверенная обложка опубликованного альбома/релиза,
  привязанная к песне по **точному официальному URL**.
- Если такой обложки нет, запрашивается официальная **Spotify oEmbed**
  через существующий общий модуль. YouTube и Apple Music продолжают
  оставаться источниками воспроизведения; они не используются как источник
  картинки (сохранено решение RUN-132).
- Во время загрузки остаётся нота; изображение показывает себя только
  после успешного `onload`. Ошибка оставляет видимую ноту; если
  опубликованная обложка сломалась, идёт одна попытка официальной Spotify.
- Кнопки на странице артиста повторяют SVG-маски и цвета стандартных
  `public-song-source`: зелёный Spotify, красный YouTube и Apple Music.
  Вся активная логика плеера/закрытия остаётся прежней, ссылки не дублируются.
- Мобильные кнопки 40×40 и загрузка изображений в существующей политике,
  с безопасным fallback для старого Safari/iPad и reduced-motion.
- Обновлены `artist-detail.css?v=3`, `artist-detail.js?v=5`, `sw.js`
  с версией public cache `v95` и тесты, с учётом прежней офлайн-работы.

## Безопасность и границы
Не изменяются Firebase Rules, документы `vmm_catalog`,
`vmm_public_pages`, черновики, внешние ссылки, радио, кристалл, DNS,
хостинг и оригинальные обложки на площадках. Из публичной страницы
используется только ранее опубликованная подборка `featuredTracks`
(до 30), не приватная библиотека.

## Тесты
- `npm test` — SUCCESS в GitHub Actions на ветке:
  **#44088273884**.
- Отдельный тест страницы артиста проверяет трёхплощадочную песню,
  переключение плеера и закрытие, запрос общей Spotify-обложки,
  появление изображения только после загрузки, fallback на ноту при
  ошибке, приоритет опубликованной обложки альбома и повторную попытку
  Spotify, отсутствие доступа к частному каталогу.
- Проверена совместимость регрессионных тестов iPad и сервис-воркера.
- **Реальная загрузка на устройстве и в сети владельца ещё требует
  визуальной проверки**: Spotify oEmbed и внешние CDN могут временно
  блокировать загрузку, в этом случае по плану остаётся нота.

## После публикации
Открой существующий профиль артиста с `artist.html?id=...`,
выбери в Studio режим «Квадратные карточки» или «Строки с обложками»
и проверь обложки/иконки. Можно открыть страницу в частной вкладке,
чтобы исключить прежний кэш Safari. Смена режима — отдельная настройка
Studio → Главная страница → Артисты и требует ручного сохранения и
публикации. Форма ссылок и содержание каталога не меняются.
