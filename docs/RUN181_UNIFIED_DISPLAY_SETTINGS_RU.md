# RUN-181 — Единый центр оформления главной и отдельные настройки профилей артистов

Дата: 17 ноября 2026 года. Репозиторий: `velardream-ctrl/velar-music-manager`.
Ветка: `fix/run180-featured-view-controls-20261117`. Основа: `5fe43465779ca0039af505fd384e8b0de8178e28`.
Продолжает RUN-180, в котором была исправлена игнорировавшаяся настройка `artists.featuredView`.

## Решение владельца
- Все настройки **оформления блоков главной страницы** должны жить в одном месте, без дублирования по вкладкам.
- В Studio: **Главная страница → Оформление главной** (ранее «Первый экран»). Отдельные группы: «Артисты на главной», «Жанры», «Темы песен», «Языки песен», «Песни в альбомах», «Обложки альбомов».
- Сами песни, языки, темы, жанры и альбомы по-прежнему редактируются в своих вкладках, но в них больше нет дублирующихся настроек внешнего вида.
- **Отдельная страница артиста** — исключение: собственная настройка `artists.detailTrackView` размещена в Studio → Главная страница → Артисты. Она НЕ регулирует главную.
- Одна песня артиста — одна строка/карточка, на ней кнопки Spotify, YouTube и Apple Music, а не три одинаковых названия песен.
- Для длинных каталогов компактный список с поиском и страницами по 25. При более чем 40 песнях карусель автоматически уступает место компактному поиску, даже если была выбрана.

## Данные и обратная совместимость
- `artists.featuredView` + `artists.songViewMode` — прежние поля оформления лучших песен **на главной**. В Studio они объединены в **один переключатель**. Режим `carousel` имеет приоритет над `classic/covers/tiles`.
- `genres.displayModes = {genres, topics, languages, albums}` — новые раздельные режимы: `compact`, `rows`, `covers`, `tiles`, `carousel`. Ранее опубликованные документы без `displayModes` автоматически сохраняют прежний режим из `genres.songViewMode` и `albums.trackView`. Сам исходный каталог не мигрируется.
- `albums.view` (обложки альбомов) управляется только из единого центра.
- `artists.detailTrackView` — только отдельная страница артиста: `compact` по умолчанию, `covers` или `tiles`.
- `artist-detail.js` берёт только утверждённые `featuredTracks` из `vmm_public_pages/landing` (до 30 треков), группирует совпадающие старые названия при **непересекающихся платформах** и не объединяет записи с двумя разными версиями Spotify под одним названием. В каждой карточке набор официальных ссылок и один iframe после нажатия. Нет автозапуска и чтения приватного каталога.

## Проверки и безопасность
- CI `npm test`: **SUCCESS** в ветке, GitHub Actions run **#44079091048** (см. SHA ветки в PR).
- Тесты проверяют отдельный layout для разных секций, поиск/страницы по 25 из 50 треков, автоматическую замену слишком длинной карусели, сохранение ссылок и переключение Spotify/YouTube/Apple Music.
- Действующая база `vmm_catalog`, Firebase/Firestore Rules, DNS, радио, анимация кристалла, авторизация, тексты песен и фонограммы не изменяются.
- Сохраняются прежние черновик и ручная публикация: изменение настройки само по себе НЕ публикует данные.
- В версии не проверена физическая работа на старом iPad Safari 12: нужна проверка пользователем после GitHub Pages deploy.
- Важно: отдельная страница артиста сейчас показывает **опубликованные лучшие песни**, а не полный приватный каталог артиста. Для отдельного полного каталога требуется безопасная публичная проекция с явным согласием на публикацию; эта задача не выполнялась.

## Инструкция
Studio → Главная страница → Оформление главной: выбрать отдельный вид каждого блока, сохранить черновик, опубликовать.
Studio → Главная страница → Артисты: выбрать «Песни в профиле артиста» для отдельной страницы, сохранить/опубликовать.
Внешние музыкальные плееры открываются только после нажатия, не требуют дублирования ссылок.
